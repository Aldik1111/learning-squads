# Сквозной протокол продукта

Дата: 14.11.2026. Среда: Next.js `http://127.0.0.1:4191`, сначала локальный Supabase, затем облачный проект Learning Squads с миграциями 001–007. Ветка `codex/a-learning-modules`, базовый HEAD `271270d7c7a1516754293eefcca30ed763794d56` плюс незакоммиченная ссылка возврата к приглашениям в CallPage и обновления протокола. Это повторяемый ручной/Playwright CLI протокол, не установленный автоматический тест и не приёмка Vercel deployment.

## Подготовка

Запустить приложение с разрешёнными переменными `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` в игнорируемом `.env.local`. Секреты, токены и localStorage в отчёт не выводить. Создать независимые браузерные контексты A, B, C; новая вкладка общего контекста не является новым гостем. В текущем облачном прогоне использованы `learning-cloud-a`, `learning-cloud-b`, `learning-cloud-c`.

1. A: имя `Cloud QA Learner A`, направление Spanish, основной язык `en`, известный `es`, доступность выключена. B: `Cloud QA Partner B`, основной `es`, известный `en`, доступность включена. C: `Cloud QA Learner C`, основной `en`, доступность выключена. Сохранить профиль и обновить страницу. Проверить значения и разделение аккаунтов. **PASS local/cloud.**
2. A создаёт команду `Cloud QA Spanish Squad`. При одном участнике вызов недоступен. B вступает; A обновляет страницу и видит двух участников. Снять все флажки получателей — кнопка вызова выключена. Выбрать B и начать вызов. **PASS local/cloud.**
3. Пока B не ответил, A возвращается в команду и пытается создать ещё одно приглашение B. Получить объяснение о существующем pending; остаться на странице без новой встречи. **PASS cloud.** Это защита от дубликата ожидания, не лимит общего количества созвонов.
4. B открывает `/notifications`, принимает приглашение, отмечает его прочитанным, обновляет страницу. Статус accepted и отметка прочтения сохранены. A видит accepted. **PASS local/cloud.**
5. A добавляет ссылку с чужим доменом — сообщение проверки без сохранения. Добавляет URL формата `https://meet.google.com/abc-defg-hij` только для технической проверки. Не переходить во внешнюю комнату. В браузерном прогоне заменить только `window.open` тестовым объектом с `location.replace()` и `close()`; не перехватывать API/ответы/серверное время. Нажать Open Google Meet; обновить страницу — время не сбрасывается; Finish this practice — интервал сохраняется и после reload остаётся завершённым. **PASS local/cloud; cloud 00:03.**
6. B открывает `/practice` для актуального heartbeat; A запрашивает Spanish-партнёра. Проверить участника B с основным `es`, не только известным `es`. Результат зависит от других доступных синтетических профилей; не считать несовпадение имени ошибкой случайного выбора. **PASS local/cloud.**
7. До принятия B пробует прямой URL разговора — доступ закрыт, Meet не раскрыт. Вернуться в приглашения и отклонить; обновить страницу — declined сохранён. A создаёт следующую встречу и отменяет приглашение; cancelled сохраняется. **PASS cloud; decline/cancel также PASS local.**
8. C вступает в команду. A выбирает B и C и отправляет ровно два приглашения. B принимает, C отклоняет. A обновляет разговор: B accepted, C declined одновременно. **PASS cloud**, разговор `ee20fecf-b4e3-4bfc-a3c2-4e076cb44bf2`.
9. B выключает доступность, обновляет страницу — выключенное состояние сохранено. При отсутствии других доступных primary-es профилей A получает сообщение «No suitable partner…», материал остаётся доступен. Выключение и отсутствие кандидатов **PASS local/cloud**. C выходит из команды и после reload видит Join squad. **PASS cloud.**
10. Оставить приглашение без ответа на 10 минут серверного времени. Обновить notifications, убедиться в expired и отсутствии Accept/Decline; проверить после reload. Не подменять timestamps и не ускорять часы клиента. **PASS cloud в 15:10 UTC**: попытка создана 14:59 UTC, разговор `b0dfb6a8-a110-48e5-bc72-ee63b51b0fe4`; expired сохраняется, кнопок принятия/отказа нет.

## Дополнительные проверки и наблюдения

- Учебный прогон [learning-flow.js](learning-flow.js) выполнен на облаке в госте C без предыдущих попыток: quiz 4/4, ответы/feedback после reload без перехвата фокуса; реальный Python 6/6; сохранённый self-check после reload; dashboard показывает оба результата. **PASS после повтора Python:** первая загрузка runtime из CDN не удалась, интерфейс показал ошибку, следующий Run checks выполнил код и сохранил результат. Ответы/API не подменялись.
- Смена локального Supabase на облачный не должна повторно использовать чужой JWT. Исправлен проектный ключ хранения; в браузере прежний локальный контекст открыл нового облачного Guest, а существующие cloud A/B сохранились. **PASS.**
- Для прямого URL ещё не принятого разговора добавлена ссылка «Check your invitations»: из ошибки доступа она ведёт к доступным Accept/Decline. **PASS cloud.**
- Cloud-страницы `/profile`, `/teams`, `/practice`, `/notifications`, `/calls` проверены при ширине 390 px: `scrollWidth === innerWidth === 390`, горизонтального переполнения нет. Снимок страницы команд просмотрен: форма, заголовки и карточки не пересекаются. **PASS.**
- Временный DNS/connection timeout во время облачного прогона не является потерей данных. После восстановления повтор запроса завершился успешно. Не выдавать транспортную ошибку за несуществующего гостя; исправление классификации передано серверному агенту.
- Не проверять имя состояния немедленно после `.check()` у серверного переключателя: дождаться ответа API и текста подтверждённого состояния. Это исключает ложный сбой проверки до завершения асинхронного сохранения.
- Снимки, логи и временные команды Playwright находятся вне репозитория. Протокол фиксирует фактические действия и ограничения; зелёный типчек не подменяет эти сценарии.

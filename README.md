# Learning Squads

MVP хакатона: учебные материалы Python, How to use AI и Spanish, проверка знаний, команды и разговорная практика. B2C веб для работающих взрослых.

**Сайт для проверки:** [Learning Squads Preview](https://learning-squads-luuljvgfs-aldik1111.vercel.app). Вход в Vercel не требуется; приложение создаёт гостевой профиль браузера. Опубликованный SHA `d922e3ce6cf1dd19bb680c646e19432ed30ce29e`. Это проверяемая версия рабочей ветки, не merge в main и не подтверждение реального созвона Meet.

Состояние 14.11.2026: код Next.js/React, API, SQL-миграции, гостевой Supabase-клиент и Python runner находятся в рабочей ветке. Облачный проект, публичный URL и сквозная приёмка фиксируются отдельно в docs/demo.md; наличие кода и зелёные локальные проверки не означают выкладку.

## Запуск

Нужен Node.js24 и npm. Для обычной разработки используйте локальный Supabase из раздела ниже, отдельно от облачной базы сдачи Learning Squads.

```sh
npm ci
```

Скопируйте `.env.example` в игнорируемый `.env.local`, заполните локальный URL Supabase и его publishable key (или legacy anon key). Не копируйте параметры облачной базы сдачи в обычную разработку. Никогда не ставьте service_role/secret в NEXT_PUBLIC-переменные. В Supabase включите Anonymous Sign-Ins и примените все `supabase/migrations/*.sql` по порядку через CLI или SQL Editor. Приложению не нужен административный ключ. Не используйте проект, БД или секреты Smart Meal.

```sh
npm run dev
```

Откройте `http://127.0.0.1:3000`. Каталог/уроки доступны даже без настроенного Supabase; профиль, отправка результатов и совместные функции покажут честную ошибку до подключения. Это не деморежим и не имитация сохранения.

## Локальный Supabase

При работающем Docker:

```sh
npx supabase@3.1.0 start
```

Конфигурация находится в `supabase/config.toml`; anonymous sign-in включён. Возьмите локальные API URL и publishable/anon key для `.env.local`. `supabase status` может выводить служебные секреты: не копируйте весь вывод в чат/логи репозитория. Нужны только публичный URL/key. Остановить только этот локальный проект: `npx supabase@3.1.0 stop` из этой папки. Не делайте reset общей или облачной БД.

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:db
python content/validate.py
python scripts/check_repository.py
npm run build
npm start
```

`test:db` требует Docker, создаёт и удаляет собственный временный PostgreSQL-контейнер без сети; не трогает другие контейнеры/тома. Проверяет настоящие SQL-функции и гонку за последнее место, но использует auth-fixture: это не проверка GoTrue, браузерной авторизации или облака. Browser/runner и сквозные результаты — в docs/demo.md и tests/e2e. CI Application checks запускается на push main/codex-веток и перед слиянием; Repository hygiene проверяет только структуру.

## Выкладка

Текущее облако и журнал ручного применения миграций: [docs/cloud-setup.md](docs/cloud-setup.md). Перед первым CLI `db push` прочитайте ограничения истории миграций в этом журнале.

Для сдачи используется проверенный неизменяемый Preview URL выше; отдельное Vercel Production не требуется критерием #19. Старый Production URL без окружения не является адресом сдачи.

**Разделение окружений настроено в Vercel, проверка новых сборок PENDING:** координатор подтвердил в UI обе переменные `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` со scope Preview только для ветки `codex/hackathon-release`. Общих Preview/Development/Production записей нет. Release-ветка опубликована на `539e821551664a7c05d8761a6f2a14df71e52697`. Локальный `npm run dev` использует локальный Supabase. Не добавляйте общие значения автоматически. #19 остаётся открытой до проверки нового обычного Preview без БД и сохранения работоспособности прежнего сдачного URL после смены настроек.

Изменения переменных действуют на новые сборки; существующий проверенный deployment сохраняет свой URL и окружение. В дальнейшем обновлять сдачный deployment следует явным выпуском из release-ветки с проверкой URL/SHA и сохранения гостевых данных. Обычный Preview без БД показывает материалы, а сохранение/профиль возвращают честную ошибку недоступности. Это не фиктивный backend.

Секреты и `.env.local` не коммитьте. Публичный URL, независимые гостевые профили, RLS и сохранение после обновления проверяются отдельно от сборки; настоящий Meet также имеет отдельный протокол. Фактическое состояние настройки и проверки изоляции — в [журнале облака](docs/cloud-setup.md).

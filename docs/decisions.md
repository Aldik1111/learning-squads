## WORKFLOW-001 v1 — PR только перед слиянием

Дата: 14.11.2026. Источник: прямое поручение владельца в чате — «PR только перед слиянием. Продолжай разработку в своей ветке без открытия новых PR».

Разработка, коммиты и публикация ветки не требуют PR. Открывать PR только при готовности части к слиянию; ранний Draft PR больше не обязателен. Координация до PR — в существующих Issues со ссылкой на ветку/SHA. Это заменяет начальное правило раннего Draft PR. Границы файлов A/B, ревью второго разработчика, проверки и защита main сохраняются. Реализация правила: AGENTS.md, CONTRIBUTING.md, README.md, docs/plan.md и инструкции обоим разработчикам. Пересмотр — по новому решению владельца с новой версией записи.

## Открыто — не превращать в дефолтные бизнес-правила
- Вместимость команды и число команд на аккаунт — до API команд.
- Длительность курса, уровни и точные материалы — до публикации.
- Порог теста и число попыток — до расчёта прохождения.
- Срок ожидания приглашения и актуальности доступности — до рабочего подбора.
- Одна или несколько встреч для 15 минут, порядок зачёта — до автоматического завершения.
- Ручное создание Meet организатором — предложенный вариант реализации, уточнить до встречи.
- Монетизация/переносы — до коммерческого запуска.
- Часовой пояс дедлайна — уточнить у организаторов.

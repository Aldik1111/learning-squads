## WORKFLOW-001 v1 — PR только перед слиянием

Дата: 14.11.2026. Источник: прямое поручение владельца в чате — «PR только перед слиянием. Продолжай разработку в своей ветке без открытия новых PR».

Разработка, коммиты и публикация ветки не требуют PR. Открывать PR только при готовности части к слиянию; ранний Draft PR больше не обязателен. Координация до PR — в существующих Issues со ссылкой на ветку/SHA. Это заменяет начальное правило раннего Draft PR. Границы файлов A/B, ревью второго разработчика, проверки и защита main сохраняются. Реализация правила: AGENTS.md, CONTRIBUTING.md, README.md, docs/plan.md и инструкции обоим разработчикам. Пересмотр — по новому решению владельца с новой версией записи.

## Открыто — не превращать в дефолтные бизнес-правила
- См. принятые ниже решения 14.11.2026: вместимость, приглашения, доступность, Meet и суммирование практики согласованы владельцем.
- Длительность курса, уровни и точные материалы — до публикации.
- Порог теста и число попыток — до расчёта прохождения.
- Срок ожидания приглашения и актуальности доступности — до рабочего подбора.
- Одна или несколько встреч для 15 минут, порядок зачёта — до автоматического завершения.
- Ручное создание Meet организатором — предложенный вариант реализации, уточнить до встречи.
- Монетизация/переносы — до коммерческого запуска.
- Часовой пояс дедлайна — уточнить у организаторов.

## MVP-RULES-001 v1 — уточнения 14.11.2026

Источник: ответ владельца «Да, принять эти правила для MVP» на объединённый вопрос в текущем чате.

- Команда: максимум 4 участника, аккаунт может состоять в нескольких командах. Проверка вместимости атомарная; старые записи не удалять автоматически при пересмотре лимита.
- Приглашение действует 10 минут с серверного времени создания. Готовность актуальна 2 минуты после последней активности аккаунта с включённым режимом. Не продлевать старые приглашения задним числом при изменении политики.
- Настоящую Meet-ссылку добавляет организатор встречи. Это не автоматическое создание конференции и не обещание гостевого доступа Google Meet.
- Языковая практика накапливается по модулю до суммарного минимума 15 минут. Отсчёт начинается с перехода; отметки и время не подтверждают присутствие. Отображение накопленного времени не означает сертифицированного освоения или автоматического зачёта теста.

Реализация: контракты, Supabase/RPC и UI задач #11–#16; проверка #17/#18. Порядок пересмотра: новое подтверждение владельца и новая версия; исторические попытки/встречи сохраняют свою историю. Это заменяет соответствующие открытые вопросы выше; остальные остаются открытыми.

## EXECUTION-001 v1 — параллельная реализация 14.11.2026

Источник: прямое поручение владельца «по одному закрывай полностью все задачи», «Запускай несколько субагентов», «Раскидай им всем все активные задачи, которые можно закрывать». На время этого выполнения разрешена реализация областей A и B через назначенных субагентов в текущей ветке с координацией файлов. Внешний разработчик B сохраняет роль; его опубликованные изменения не перезаписываются. Root отвечает за интеграцию, проверки и закрытие только выполненных критериев. Ранние PR не открываются, main не обходится.

Отдельные Supabase/Vercel проекты для Learning Squads разрешены ответом «Нет — нужно создать отдельные проекты». Это не разрешение оплачивать тарифы и не разрешение использовать инфраструктуру Smart Meal. Доступы не включать в Git или комментарии.

## DEPLOYMENT-001 v1 — публичный Preview для проверки

Дата: 14.11.2026. Источник: прямые ответы владельца «Да, подключить только learning-squads» и «Да, сделать Learning Squads публичным», поручение дать работающую ссылку второму участнику.

GitHub App Vercel получает доступ только к репозиторию Learning Squads. У отдельного проекта `learning-squads` выключено требование входа Vercel, чтобы гостевое приложение открывалось второму участнику и жюри. Это не отключает Supabase Anonymous Auth, RLS, серверную проверку пользователя или защиту source maps. Публикуется Preview рабочей ветки; main и его защита сохраняются, PR создаётся только перед слиянием. Журнал окружения и точные URL/SHA — `docs/cloud-setup.md`; приёмка — `docs/demo.md`. Пересмотр — отдельное решение владельца с новой версией, без изменения истории попыток.

## Границы
Ваши пути перечислены в ownership.md. UI, content и E2E — A.
После bootstrap передайте layout/globals и страницы A.
Не перезаписывайте интерфейс ради интеграции: предоставьте функции и компоненты.
Сервер проверяет сессию; userId из тела не доказывает права. RLS, повторы, атомарные переходы.
Приглашения pending → accepted/declined/cancelled/expired; повтор не создаёт новую встречу.
У встречи несколько независимых приглашений. Отметка перехода привязана к аккаунту/встрече; повтор не сбрасывает.
Python отделён от сессии приложения, worker не является достаточной границей безопасности. Результат — самопроверка.
Сроки доступности/приглашений, правила команды/тестов/15 минут не выдумывать: согласовать в Issue решений.
Нет AI API, оплаты и слотов бронирования в ядре.

Миграции через Git; применённые не переписывать. Разделить dev и сдаваемую БД. Не сбрасывать общий контур без согласования.
Работайте в своей ветке codex/api-* с небольшими тематическими коммитами и пушами без раннего PR. Состояние и зависимости — в Issue. PR открывайте только перед слиянием готовой части, с проверкой A. Каркас и контракты передавайте A своевременно, не удерживайте их до конца MVP. В README зафиксировать реальные команды и состояние деплоя.

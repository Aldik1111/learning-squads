## Контрольные точки
1. Опубликованный сайт + настоящий гость + сохранённый профиль.
2. Материал → тест → результат → восстановление прогресса.
3. Реальное выполнение Python и обработка ошибок.
4. Создание команды и участие разных аккаунтов.
5. Доступность → подбор → уведомление → ответ.
6. Групповой созвон → настоящая Meet-ссылка → сохранение отметки.
7. Независимые браузерные сессии проходят опубликованную версию.
8. Сайт, публичный GitHub и PDF проверены без входа владельца.

Работа идёт в отдельных ветках без ранних PR. B сначала готовит небольшие части bootstrap/контрактов и публикует ветку; PR открывает, когда они готовы к слиянию и передаче A. Это не повод ждать окончания всего MVP. До интеграции A может готовить материалы и изолированные UI-компоненты в своих файлах, не создавая второй каркас или API. Резерв на интеграцию/сдачу — последние 20–25% доступного времени. Дата не является доказанной оценкой выполнимости. Отставание и изменение объёма сообщать явно.

## Исходные контрольные точки MVP (история)
1. Опубликованный сайт + настоящий гость + сохранённый профиль.
2. Материал → тест → результат → восстановление прогресса.
3. Реальное выполнение Python и обработка ошибок.
4. Создание команды и участие разных аккаунтов.
5. Доступность → подбор → уведомление → ответ.
6. Групповой созвон → настоящая Meet-ссылка → сохранение отметки.
7. Независимые браузерные сессии проходят опубликованную версию.
8. Сайт, публичный GitHub и PDF проверены без входа владельца.

Работа продолжается в согласованных codex-ветках и непересекающихся областях файлов без ранних PR. PR открывается только перед слиянием готовой части; до него изменения и проверки фиксируются в существующей issue. Общие контракты согласуются до параллельных правок, новый каркас и второй API не создаются. После локальной интеграции отдельно проверяются миграции, опубликованная сборка и независимые браузерные профили. Дата не является доказанной оценкой выполнимости; отставание, внешние зависимости и изменение объёма сообщаются явно.

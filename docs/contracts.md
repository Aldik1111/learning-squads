# Контракты Learning Squads v2

## Расширение курсов и доска заданий — 15.11.2026

Additive010–011 проверены в отдельной PostgreSQL и применены атомарно к существующему локальному Supabase Learning Squads без сброса данных, с записью истории миграций. Это не доказательство облачной выкладки. `Track` включает `python`, `how-to-use-ai`, `spanish`, `python-automation`, `ai-for-work`, `french`; по три модуля и авторское задание на модуль. Четыре Python/AI курса используют автоматические группы до четырёх участников. Spanish/French остаются языковыми курсами без групп. `LearningModule` содержит `courseId` и `task`; публичная выдача не содержит ключей quiz или эталонного Python.

- `getTaskBoard(courseId?)` / `GET /api/tasks?courseId=…` возвращает `TaskBoardItem[]`: определение задания и собственный результат. До сохранения status=`not_started`, revision=0, summary пустое, link/sharedGroupId/updatedAt=null. Отображается текущая версия определения; старые определения и результаты сохраняются в БД.
- `TaskDefinition`: id, version, moduleId, contentVersion, courseId, title, description, acceptanceCriteria. Привязка к опубликованной версии модуля неизменяема.
- `updateTaskResult(taskId, taskVersion, input, requestId)` / `PUT /api/tasks/:id`: input содержит status=`not_started|in_progress|done`, summary (до4000 символов), link=null или HTTPS URL до2048 символов без credentials, shareWithGroup, shareGroupId=null или UUID явно выбранной группы, expectedRevision. Для Done нужен непустой после удаления окружающих пробелов summary; дополнительных порогов длины/quiz/attendance нет. Done — собственная отметка учащегося, не сертификация.
- `TaskResult`: taskId, taskVersion, userId, userName, status, summary, link, sharedGroupId, revision, updatedAt. Сервер определяет владельца по JWT. `expectedRevision` сравнивается под блокировкой; конфликт требует явной сверки и повторного редактирования. Один requestId с тем же input возвращает актуальную запись без повторного изменения; другой input с этим ID — CONFLICT.
- По умолчанию результат личный. Для shareWithGroup=true требуется shareGroupId, совпадающий с действующим членством пользователя в группе именно этого курса. UI фиксирует ID в момент открытия редактора/явного выбора: переназначение не должно незаметно подставлять новую группу в save. Для false нужен shareGroupId=null. Языковые задания нельзя публиковать в группе.
- `getGroupTaskResults(groupId)` / `GET /api/course-groups/:id/tasks` возвращает только явно опубликованные результаты нынешних участников этой группы и этого курса. Чужая группа — FORBIDDEN. При выходе/переназначении trigger очищает публикацию и повышает revision, сохраняя личный текст/ссылку/статус. Возвращение в прежнюю группу не восстанавливает публикацию. Повтор старого requestId также не восстанавливает sharing.
- Ссылки только отображаются как внешние HTTPS ссылки. Сервер не загружает их содержимое; загрузки файлов нет. Текст результата остаётся обычным текстом, не HTML.
- `Call.targetLanguage` берётся из сохранённого языка встречи. Если передан moduleId, SQL сверяет язык с авторской привязкой модуля (Spanish/es либо French/fr); программный модуль не может получить языковую практику. Интервалы по-прежнему суммируются отдельно по moduleId, цель15минут, без доказательства посещения.
- Python self-check использует сохранённые caseIds конкретного exerciseId/exerciseVersion, без прежнего жёсткого списка одного упражнения. Результат остаётся недоверенной самопроверкой. Прогресс группы содержит все три модуля её курса и не раскрывает ответы других участников.

Уже опубликованные ключи сравниваются с БД и не обновляются. `tests/server/task-board-integration.sql` проверяет приватность, публикацию/отзыв, устаревшие редакторы, повторы, поля и языковые пары; изолированный DB harness также проверяет конкурентные сохранения и вместимость нового курса. ## Сессия и ошибки

`ensureGuestSession(): Promise<{userId:string}>` восстанавливает Supabase-сессию браузера или создаёт anonymous user. Локальное хранилище разделено по Supabase origin: `learning-squads-auth:<origin>`. Прежняя общая запись переносится только при совпадении JWT issuer с текущим проектом; сессия другого проекта не переиспользуется. Сервер всё равно проверяет токен — issuer здесь лишь подсказка переноса хранилища. Одновременное создание координируется promise и Web Locks. Никаких email/паролей в пользовательском потоке. Совместное использование одного профиля браузера даёт общие данные; разные профили независимы.

Защищённые вызовы отправляют bearer JWT. Сервер проверяет его `auth.getUser(token)` и вызывает PostgreSQL RPC от имени пользователя; `auth.uid()` определяет владельца данных. `userId` в JSON не используется для авторизации. Service-role ключ приложению не нужен. Таблицы закрыты RLS и отсутствием прямых grants; только узкие RPC имеют execute для authenticated. Внутренние функции и ключи оценивания закрыты.

Ответ: `{data:T}` или `{error:{code,message}}`. Клиент бросает `ApiError` с кодом и понятным сообщением. Коды перечислены в `AppErrorCode`, включая SESSION_REQUIRED/FORBIDDEN/INVALID_INPUT/NOT_FOUND/CONFLICT/SQUAD_FULL/NO_AVAILABLE_PARTNER/INVITATION_PENDING/INVITATION_EXPIRED/INVITATION_CANCELLED/MEET_LINK_MISSING/SERVICE_UNAVAILABLE. Нет фиктивного успеха при отсутствующем окружении. Сбой сети/5xx/429 при проверке identity provider возвращает SERVICE_UNAVAILABLE503, а не SESSION_REQUIRED401; временный отказ не означает потерю гостевого профиля. Таймаут HTTP — технические 20 секунд, не лимит учебной попытки.

## Методы

- `getCourses()`, `getModule(moduleId)` доступны без сессии. Возвращают материалы/стартовый Python, без answerKey/referenceFile/решений.
- `getProfile()`, `updateProfile(ProfileInput)`: имя, track, level, primaryLanguage, knownLanguages, timezone, availableForCalls. Неподтверждённое владение языком остаётся самооценкой.
- `submitQuiz(moduleId, contentVersion, answers, requestId)` возвращает сохранённый `QuizAttempt`: id, moduleId, contentVersion, answers, items с correctOptionId/correct/explanation, submittedAt. Оценивание в PostgreSQL по неизменяемому снимку ключей. Нет порога прохождения или числа попыток.
- `submitPythonResult(PythonRunResult, requestId)` хранит честно помеченную `self-check`: exerciseId/version, status, passed/total. Прерванные/error/timeout/cancelled результаты не объявляются успешными. Код пользователя и stdout не сохраняются. Это недоверенная самопроверка, не серверная квалификация.
- `getProgress()` → quizAttempts/pythonAttempts по submittedAt DESC и practice `{moduleId,seconds,minimumPracticeMinutes}`. Другие пользователи этих данных не видят.
- `Course` теперь имеет `category: "programming" | "languages" | "ai"` и `collaborationMode: "group" | "language-partner" | "self-paced"`. Python и How to use AI используют автоматические группы; Spanish не создаёт группу, сохраняет материалы/quiz и подбор языкового собеседника.
- Старые `findSquads/createSquad/joinSquad/leaveSquad/createSquadCall/setMeetLink` оставлены только как исторические TypeScript exports для совместимости старых импортов; HTTP возвращает403, прямые manual-group/Meet-write RPC отозваны. Ручного каталога/названия/вступления в группу больше нет. Старые таблицы и история не удалены.
- `setCallAvailability(boolean)`, `heartbeat()`: готовность и актуальность2мин; UI отправляет heartbeat, когда видимая страница активна.
- `requestLanguagePartner(language,requestId,moduleId?)`: случайный другой профиль с указанным основным или добавленным известным языком и актуальной включённой доступностью.
- `getMyCalls()` возвращает языковые разговоры без создания Google events; `getCall(id)` доступен организатору и принявшим участникам. Call.participants включает invitationId (null у организатора), status и transitionedAt. `meetStatus` показывает pending/ready/unavailable, `meetUrl` выдаётся только проверенным Google provider. Сначала RPC проверяет доступ, после внешнего запроса доступ проверяется повторно.
- `getNotifications()`, `markRead(id)`, `acceptInvitation(id)`, `declineInvitation(id)`, `cancelInvitation(id)`. Один invitation на получателя/call; групповые ответы независимы. pending → accepted/declined/cancelled/expired. Срок10мин; отмена только отправителем, ответ только получателем. Повтор того же принятого действия не создаёт дубль. Техническая защита от спама языковых приглашений: у пары отправитель→получатель допускается одно ожидающее приглашение независимо от нового requestId и другой встречи. Создание сериализуется по отправителю; повтор до ответа/отмены/истечения получает INVITATION_PENDING. Это не квота созвонов: после конечного ответа можно создать новую встречу. Истечение проверяется по clock_timestamp после получения блокировки строки, чтобы запрос, ожидавший блокировку, не принимал просроченное приглашение.
- Клиент не задаёт Meet URL. `setMeetLink` запрещён HTTP/RPC. Автоматический Google Calendar provider использует только server-only OAuth, проверяет идентификатор/времена события и HTTPS Meet URL; отсутствующая конфигурация честно даёт unavailable. Новые group meetings вообще не имеют URL-колонки в БД.
- `recordMeetTransition(callId)` — разрешённому участнику языковой встречи; HTTP предварительно проверяет готовый provider URL. Серверное время фиксируется один раз; повтор не сбрасывает. Прямой собственный RPC timestamp остаётся недоверенной отметкой клика и не доказывает посещение. Групповой календарь не симулирует языковую практику.
- `finishPractice(callId)` — явное завершение измерения для модуля после перехода. Серверное endedAt фиксируется один раз. Итог — объединение пересекающихся завершённых интервалов пользователя по модулю; один и тот же промежуток не суммируется дважды. Незавершённый таймер не входит в накопленный итог. Это время от перехода, не доказательство присутствия; завершение курса автоматически не выставляется.

## Автоматические группы, расписание, чат и календарь

Источник DTO — `src/contracts/index.ts`; HTTP namespace `study-availability` и `course-groups`. Все методы ниже требуют bearer настоящего гостя; userId из входа не используется.

- `AvailabilitySchedule = {timezone, windows:[{weekday,startMinute,endMinute}]}`. weekday0=Sunday…6=Saturday, целые минуты0…1440, end>start, каждое окно минимум15мин, 1…100 окон, пересечения в один weekday запрещены. Overnight задаётся отдельными дневными окнами. timezone проверяется по базе IANA PostgreSQL. 100 окон — техническая граница payload, не квота учёбы/встреч.
- `getStudyAvailability(): StudyAvailability|null`; `updateStudyAvailability(schedule): StudyAvailability`, где StudyAvailability дополнительно имеет updatedAt. После сохранения UI перечитывает `getMyCourseGroups()`: несовместимые группы автоматически меняются, совместимые группы других курсов остаются. Все изменения одной транзакцией, старое membership закрывается leftAt, попытки/прогресс остаются; доступ к чату/прогрессу/календарю прежней группы теряется. История членства не удаляется.
- `enrollCourse(courseId,requestId): CourseGroup` только для group-курсов Python/AI; без расписания AVAILABILITY_REQUIRED. На курс максимум одна активная группа аккаунта, разные курсы разрешены. Повтор course enrollment не дублирует membership; тот же requestId другого course даётCONFLICT. Spanish enrollment в группы отклоняется; изучение его материалов и языковой подбор от этого не зависят.
- `getMyCourseGroups()` и `getCourseGroup(id)` возвращают только собственные активные группы: `{id,number,courseId,createdAt,members:[{userId,name,joinedAt}],commonWindows:[{startsAt,endsAt}],status}`. Номер монотонно назначается внутри курса. Максимум4 участника; нет подходящей группы — новая numbered группа со статусомwaiting. Ready требует минимум2 участников и общее окно. Нет ручного выбора группы.
- Подбор под course advisory lock проверяет пересечение расписаний ВСЕХ участников плюс нового гостя, минимум15мин; попарной совместимости недостаточно. Сортированные course locks при смене расписания и user lock при записи предотвращают конкурентное переполнение/двойное членство.
- Окна раскрываются в реальные UTC-интервалы на следующие28дней. DST spring-gap endpoint, который не проходит round-trip wall-time→UTC→wall-time, пропускает конкретное несуществующее вхождение. Для неоднозначного fall-back endpoint используется стандартное время PostgreSQL. IANA timezone не превращается в постоянный offset. Полные чужие расписания не раскрываются: группе доступны только общие окна.
- `getGroupMessages(id): GroupMessage[]` — последние100 сообщений в хронологическом порядке; `sendGroupMessage(id,body,requestId)` — текст1…2000 символов, idem replay, другой текст/группа с тем же requestId даётCONFLICT. Только активный участник читает/пишет; прямой доступ к таблице закрыт.
- `getGroupProgress(id): GroupMemberProgress[]` — агрегаты участников только данного курса: число quiz attempts, latest score/total, Python passed/total, practiceSeconds. Не выдаёт ответы/ключи/полные попытки или результаты других курсов. Python по-прежнему недоверенный self-check. В текущих group-курсах языковой практики нет, practiceSeconds0.
- `getGroupMeetings(id): GroupMeeting[]` — календарь активной группы, последние30 записей. При минимум2 участниках автоматически гарантирует одну текущую/ближайшую15-мин встречу в общем окне; повтор GET не дублирует запись. Еженедельная обязательная частота не вводится. `createGroupMeeting(id,requestId)` возвращает ту же текущую/ближайшую встречу при пересечении; после её окончания допускается следующая. Общей квоты созвонов нет.
- `GroupMeeting = {id,groupId,startsAt,endsAt,status,meetUrl,createdBy,createdAt}`. DB хранит только pending/cancelled и времена, не URL. После проверки membership сервер обогащает данные через Google Calendar: ready/pending/unavailable, URL|null. Provider idempotency основана на DB UUID и метаданных события, 409 получает существующее событие. Прошедшие строки читают существующее provider event с createIfMissing=false, сохраняя готовую ссылку в истории; прошедшие/отменённые строки не создают новые provider events. Google не получает email участников или приглашения.
- Будущие встречи, несовместимые с новым составом/расписанием, отмечаютсяcancelled; начатые и прошлые сохраняются. SQL обновления расписания возвращает внутренний `_cancelledMeetings` только с id/groupId для cleanup; HTTP удаляет это поле после попытки provider cancel. При недоступном Google отмена в приложении уже действует, повтор сохранения/чтение календаря повторяет cleanup. URL отменённой встречи не выдаётся. После ensure сервер перечитывает membership/status, чтобы не вернуть URL устаревшего права доступа. Если членство уже отозвано, additive009 RPC ls_get_cancelled_group_meetings разрешает cleanup только запрошенных id/groupId из исходно разрешённого снимка, со статусомcancelled и createdAt не позже завершения членства. Он не выдаёт URL или новые post-departure записи. Сервер удаляет только подтверждённые отменённые events и возвращает исходную ошибку доступа; действительные встречи остальных не удаляются.

Google OAuth переменные только server-side: GOOGLE_CLIENT_ID/SECRET/REFRESH_TOKEN, опциональный GOOGLE_CALENDAR_ID. GOOGLE_MEET_OPEN_ACCESS по умолчанию false; включение требует отдельного согласия организатора и Google scope meetings.space.settings, иначе нельзя обещать OPEN-доступ. Приложению не нужен Supabase service_role, нет RPC для принятия клиентского provider URL. Возможность открыть уже известную внешнюю Meet-ссылку определяется Google; контроль API не означает удаление ссылки из памяти бывшего участника.

## Повторы и версии

`requestId` — UUID одной логической команды. UI создаёт его при начале попытки/создания команды/приглашения и сохраняет при транспортном retry. Новый пользовательский запуск создаёт новый UUID. Повтор с тем же payload возвращает исходный результат, изменённый payload — CONFLICT. Нельзя автоматически назначать новый ID при неизвестном исходе запроса.

Снимки contentVersion/exerciseVersion не меняют прошлые попытки. Первые материалы согласованы с форматом `content/README.md`; ключи опубликованного quiz хранятся в versioned SQL seed. Изменения после применения — только новой миграцией/версией; генератор первой миграции отказывается перезаписывать существующую.

Локальные модели KnowledgeCheck адаптируются из QuizAttempt; initialAttempt восстанавливает результат. PythonExercise получает `PythonExerciseData`, onResult — `PythonRunResult`; изоляцию и ограничения runner описывает собственный README. Production-клиент не импортирует fixtures.

## Проверки и пределы

`npm test` проверяет публичные payload/входы; `npm run test:db` создаёт отдельную временную PostgreSQL без сети и проверяет миграции, SQL-оценивание, права, идемпотентность, выбор получателей, конкурентный последний слот, объединение интервалов. Скрипт сначала проверяет исторические001–007, затем применяет008 и проверяет новую политику: ALL-member matching,8 конкурентных вступлений→2 группы по4, повтор одного гостя, приватность/перенос, DST, сохранение языковой ветки. Auth-fixture имитирует auth.uid(), а не GoTrue: анонимный вход, PostgREST, сохранение в независимых браузерах и выкладку обязательно проверять отдельно.

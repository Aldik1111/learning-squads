# Separate meeting decisions from suggestions

Meeting notes mix ideas, agreements, and next steps. Turning every suggestion into an assigned task can create work nobody accepted. A useful summary preserves the difference between what was discussed and what was decided.

## Extract with evidence

Fictional notes: "Rae suggested a weekend workshop. The team agreed to run a 20-minute weekday session instead. Dev will draft an agenda. No due date was set."

The weekend workshop is a proposal, not the final decision. The weekday session is a decision. Drafting the agenda is an action with owner Dev and an unknown due date. A reviewable result includes three sections: decisions, actions with owner/due fields, and open questions. Keep a brief supporting phrase beside each item.

A prompt can ask: "Use only these notes. Separate agreed decisions from suggestions. For each action, provide task, owner, due, and evidence. Use null for an unstated owner or date. List unresolved details separately. Do not assign people yourself."

If a name appears near an action, that alone does not prove ownership. Likewise, a meeting date is not automatically the action's deadline. Check the wording that establishes the commitment. If the notes are ambiguous, label the ambiguity for a human follow-up instead of filling the gap.

## Practice

Use: "Ari suggested a new logo. The team decided to keep the current logo for the demo. Bo will check the landing-page text by Tuesday. Someone should test mobile; no owner was chosen." Create a decision list, an action table, and open questions. Keep the mobile owner unknown and do not treat the suggested logo as approved.

Submit the structured summary and one corrected misclassification. An AI tool is optional; this is an extraction and review exercise, not a recording or automatic assignment service. Use fictional notes and obtain appropriate permission before handling real meeting material elsewhere.
